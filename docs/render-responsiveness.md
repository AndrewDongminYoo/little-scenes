# Rendering responsiveness revision

Base: 83d0e22895bcb021c8718d9c33f83c624b3f8cef. This revision preserves the stroke/sprite material renderer.

## Changes

- Clip the shared artwork to 360 × 640. A padded CanvasKit regression checks transparent letterbox margins at four rain times.
- Gallery cards use generated 360 × 640 PNGs. They no longer load fonts or prepare full scene resources. `npm run render:check` regenerates these assets using the same artwork renderer.
- On iOS/Android, prepare resources on a lazily created, dedicated Worklets runtime. Mutable caches live separately in each runtime. No graphics objects are disposed while a mounted canvas/export may still reference them.
- Record export React content on the RN runtime, then rasterize the immutable SkPicture and encode PNG on the rendering runtime. The surface and snapshot are released in `finally`; the picture is released only after the encoding promise settles.
- Web explicitly retains a synchronous fallback after yielding. It is **not** a Web Worker implementation.
- Touch restoration has an independent clock. Pausing rain/Reduce Motion stops automatic rain but does not leave user-created wipe marks indefinitely. Both clocks freeze for sharing and when the scene is inactive.
- Add the requested dancheong palette. Existing persisted `red` records remain selectable rather than silently changing a saved work.
- Attach vertical trailing punctuation to its preceding cell; avoid a dangling comma below the column.
- Use SDK 58's declarative NavigationBar to hide Android navigation in immersive mode and restore it on exit/unmount.

## API evidence

Installed sources were checked rather than assuming an older API:

- react-native-worklets 0.13.0: `createWorkletRuntime`, `runOnRuntimeAsync`, serializable typed arrays and error propagation.
- react-native-skia 2.14.0: `SkiaWorkletSerialization.ts` registers transfer of Skia NativeState objects by reference and restores their prototypes on the target runtime. CPU `Surface.Make` is used, not a UI-owned GPU surface.
- Expo NavigationBar SDK 58: https://docs.expo.dev/versions/v58.0.0/sdk/navigation-bar/ . `NavigationBar hidden` replaces deprecated visibility setters.

## Verification and remaining gate

Local Linux: typecheck, lint, 26 tests and CanvasKit output/letterbox regressions pass. iOS/Android/Web bundles compile. These are not native execution or responsiveness measurements.

Before merging, both native CI smoke flows must exercise the new cross-runtime resource transfer and PNG encoding. In addition, check actual-device cold text changes, 40-character input, memory after repeated settings, pause-and-drag restoration, Reduced Motion, and Android gesture/three-button navigation. No claim of 60fps or a particular mobile latency is made.

The checked-in `examples/` images are previous examples; current render evidence is generated by CI. The new bundled previews are regenerated in this revision.

## Baseline native run 39242000531

The base commit's quality and native builds passed, but native execution did not. Android aborted around two seconds after launch (SIGSEGV, Hermes/GWP-ASan stack); the root cause is not established. iOS failed while starting/connecting the Maestro XCUITest driver, before the application flow. Do not attribute either failure to this revision or claim it fixes them without a new native run.

This revision also creates evidence directories before tests and retains Android logcat/activity state on failure, plus iOS device diagnostics. Diagnostic steps do not swallow test failures. No memory safety instrumentation is disabled, and no test assertion is weakened.
