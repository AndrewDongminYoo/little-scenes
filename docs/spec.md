당신은 React Native 개발과 인터랙티브 그래픽 구현에 능숙한 모바일 프로덕트 엔지니어다.

아래 제품을 iOS와 Android에서 실행할 수 있는 React Native 프로젝트로 부트스트랩하라. 제품의 핵심 흐름과 첫 두 작품을 실제로 구현하고, 실행 방법과 검증 결과를 함께 제공하라.

먼저 현재 저장소와 AGENTS.md 등 프로젝트 지침을 확인하라. 기존 프로젝트가 있다면 그 구조와 패키지 매니저를 존중하고, 빈 저장소라면 아래 기본값으로 시작하라.

## 1. 제품의 목적

앱 가칭은 **Little Scenes**다. 이름과 앱 식별자는 나중에 쉽게 변경할 수 있게 관리한다.

사용자가 짧은 문구를 입력하면, 그 문구가 재료감과 움직임을 가진 작은 작품으로 표현된다. 사용자는 작품을 감상하고, 간단한 터치나 드래그로 반응을 경험하고, 마음에 드는 순간을 캡처해 공유한다.

핵심 사용자 흐름:

1. 갤러리에서 작품을 고른다.
2. 자신의 문구를 입력한다.
3. 색이나 분위기를 간단히 조절하고 작품을 만져본다.
4. 조작 UI를 숨겨 감상하거나 직접 스크린샷·화면 녹화를 한다.
5. 앱의 공유 버튼으로 작품만 담긴 PNG를 공유한다.

첫 실행부터 잘 구성된 기본 작품을 보여준다. 사용자가 아무것도 설정하지 않아도 앱의 매력을 이해할 수 있어야 한다.

성공 기준은 처음 들어온 사용자가 약 30초 안에 자기 문구를 넣은 작품을 만들고 공유 흐름까지 도달하는 것이다.

## 2. 첫 구현 범위

첫 버전은 다음 두 작품으로 구성한다.

| 작품          | 핵심 표현                                                | 기본 감상 방식                        |
| ------------- | -------------------------------------------------------- | ------------------------------------- |
| 프랑스 십자수 | 린넨 천에 X자 스티치로 수놓아진 사용자 문구              | 수놓기 모션이 끝나면 완성된 정지 작품 |
| 빗물 유리창   | 비에 젖은 유리에서 발수 처리된 글자 영역이 드러나는 표현 | 비가 계속 흐르는 모션 작품            |

공통 기능은 작품 갤러리, 문구 편집, 작품별 소수의 조절 기능, 감상 모드, 재생 제어, PNG 공유, 최근 설정의 로컬 저장이다.

로그인, 서버, 공개 피드, 결제, 원격 콘텐츠 배포, 범용 템플릿 편집기는 첫 범위에서 제외한다. 앱 내부의 MP4·GIF 인코딩도 후속 작업으로 남긴다.

모든 기본 작품과 폰트는 오프라인에서 동작해야 한다.

## 3. 기술 기본값

- React Native + Expo + TypeScript strict.
- iOS와 Android 스마트폰, 세로 방향을 우선 지원한다.
- Expo Router로 갤러리와 작품 상세 화면을 연결한다.
- 작품 그래픽은 React Native Skia로 구현한다.
- 모션은 Reanimated, 터치는 React Native Gesture Handler를 사용한다.
- PNG 임시 파일과 공유는 Expo FileSystem 및 Expo Sharing을 사용한다.
- 최근 문구와 작품 설정은 AsyncStorage 등 작은 로컬 저장소로 관리한다.
- 일반 조작 UI는 React Native 기본 컴포넌트와 StyleSheet를 중심으로 구현한다.

설치 시점의 안정적인 Expo SDK를 선택하고, 해당 SDK가 안내하는 React Native·Skia·Reanimated·Worklets 호환 조합을 확인하라. Skia의 패키지명과 버전도 Expo 지원 경로를 확인해 결정한다.

라이브러리마다 독립적으로 최신 major를 설치하거나, 서로 다른 세대의 문서와 API를 섞지 않는다. 사용하려는 API는 설치된 패키지의 실제 타입 정의와 공식 문서를 대조한다.

개발 빌드를 기준으로 실행 가능성을 확인한다. 선택한 조합의 Expo Go 지원 여부를 제품 동작의 전제로 삼지 않는다.

## 4. 화면과 공통 UX

### 갤러리

작품의 실제 결과를 크게 보여주는 갤러리를 만든다.

- 각 카드에는 작품 미리보기, 이름, 한 줄 설명, 정적·모션 구분을 표시한다.
- 미리보기는 해당 작품의 실제 렌더링 결과에서 만든다.
- 첫 화면에서는 두 작품 모두 쉽게 발견할 수 있게 배치한다.
- 카드 전체를 터치하면 작품 화면으로 이동한다.
- 갤러리에서는 정지 미리보기를 사용해 여러 애니메이션이 동시에 실행되지 않게 한다.

앱의 바탕은 따뜻한 중성색과 절제된 타이포그래피로 구성한다. 작품의 질감과 색이 시각적 중심이 되게 한다.

### 작품 화면

작품을 가장 큰 영역에 배치하고, 조작 도구는 작은 하단 패널에 모은다.

공통 조작은 다음과 같다.

- 문구 편집
- 작품별 색상·분위기 조절
- 재생·일시정지 또는 다시 재생
- 감상 모드
- 이미지 공유

문구 편집은 별도 화면보다 작은 편집 패널이나 모달로 제공한다. 한국어 키보드가 열린 상태에서도 입력값과 적용 버튼에 접근할 수 있어야 한다.

매개변수를 많이 노출하지 않는다. 작품별 추가 조절은 두세 개 이내로 제한하고, 기본값 자체가 보기 좋게 구성한다.

### 감상 모드

- 앱의 버튼, 제목, 편집 패널을 숨긴다.
- 플랫폼에서 가능한 범위로 상태바를 숨긴다.
- 작품을 한 번 탭하면 조작 UI를 복원한다.
- 작품의 드래그 제스처와 UI 복원용 탭을 구별한다.
- 첫 진입 때만 짧은 종료 안내를 보여주고 자동으로 숨긴다.
- 접근성 사용자는 명확한 액션으로 감상 모드를 종료할 수 있어야 한다.

작품의 기본 구도는 9:16으로 한다. 다른 화면 비율에서는 작품을 늘이거나 잘라내지 않고 비율을 유지하며, 남는 영역은 장면에 어울리는 배경색으로 처리한다.

## 5. 공통 텍스트 처리

첫 버전은 한글, 영문, 숫자, 공백, 기본 문장부호를 지원한다.

- 한글 글리프가 포함된 적절한 라이선스의 폰트를 앱에 번들한다.
- 최대 40 grapheme, 최대 3줄을 기본 입력 제한으로 한다.
- 사용자 편집값은 유지하고, ‘적용’ 시 입력 제한을 검증한다.
- 한글 조합 중인 문자열을 매 입력마다 자르거나 정규식으로 제거하지 않는다.
- 이모지 등 지원하지 않는 문자가 있으면 이유를 안내하고 수정을 요청한다.
- 공백만 입력한 경우 안내하고 공유를 비활성화한다.
- 기본 예문은 최초 진입 때 제공하며, 사용자가 지운 문구를 몰래 복원하지 않는다.

실제 폰트로 전체 문단을 레이아웃한 후 글자 영역을 마스크로 생성한다. 문자를 하나씩 쪼개 임의의 고정 너비로 배치하지 않는다.

텍스트 크기는 정해진 작품 영역 안에서 자동 조절한다. 최소 가독 크기에서도 들어가지 않으면 문구를 줄이도록 안내하고, 글자가 잘린 결과를 그대로 공유하지 않는다.

텍스트 레이아웃과 마스크 생성은 문구·폰트·크기 등 관련 설정이 바뀔 때 수행한다. 매 애니메이션 프레임마다 다시 계산하지 않는다.

비동기 마스크 생성이 겹치는 경우 늦게 완료된 이전 결과가 최신 문구를 덮어쓰지 않게 한다.

## 6. 작품 1 — 프랑스 십자수

### 시각적 목표

아이보리 린넨 천을 가까이서 바라보는 구도다. 입력한 문구가 실제 실로 수놓아져 있고, 천의 짜임과 작은 구멍, 실의 교차와 얕은 그림자가 느껴져야 한다.

기본 문구는 **“오늘도, 천천히”**로 한다.

핵심 표현은 다음과 같다.

- 글자를 이루는 실제 X자 스티치.
- 천 표면의 미세한 직조 패턴.
- 스티치 두 대각선의 교차 순서와 높이 차이.
- 실의 두께, 부드러운 하이라이트, 얕은 그림자.
- 과하지 않은 색과 굵기의 작은 변화.
- 문구 주변의 충분한 여백.

글자 형태 자체가 스티치의 집합으로 만들어져야 한다.

### 구현 방향

1. 입력 문구를 글자 마스크로 렌더링한다.
2. 마스크를 일정한 격자로 샘플링한다.
3. 글자 영역에 해당하는 셀에 두 대각선이 교차하는 X 스티치를 그린다.
4. 실의 명암과 천 배경을 합성한다.

패턴의 작은 무작위 변화는 seed로 결정한다. 동일한 문구·설정·seed는 동일한 작품을 만들어야 한다.

천의 반복 질감과 많은 스티치는 캐시 가능한 그림이나 배치 렌더링으로 처리한다. 스티치마다 React Native View를 생성하지 않는다.

### 모션과 인터랙션

- 처음 진입하거나 새 문구를 적용하면 약 1~2초 동안 스티치가 차례로 생긴다.
- 수놓기가 끝나면 완성된 정지 상태로 유지한다.
- ‘다시 수놓기’로 같은 모션을 다시 볼 수 있다.
- 작품을 드래그하면 광원 위치가 조금 변해 실의 입체감이 반응한다.
- 움직임은 작게 유지하고 글자 형태나 가독성을 훼손하지 않는다.

### 조절 기능

- 문구
- 실 색상 프리셋: 짙은 빨강, 남색, 올리브
- 스티치 크기: 촘촘하게 / 보통

시각적 합격 기준: 정지 화면에서도 문구를 읽을 수 있고, 확대했을 때 X자 실의 교차와 천의 질감이 드러나야 한다.

## 7. 작품 2 — 빗물 유리창

### 시각적 목표

비에 젖은 유리창에서, 발수 처리된 문구 부분에 물이 덜 머물면서 글자가 드러난다.

기본 문구는 **“흐르는 대로”**로 한다.

사용자의 “위로 비가 내리는 화면”은 아래에서 위로 흐르는 비로 해석한다. 비 방향은 한 설정값에서 바꿀 수 있게 구현한다.

글자는 젖은 유리와 상대적으로 마른 영역의 차이로 읽혀야 한다. 글자 경계에 맺히는 작은 물방울과 하이라이트가 발수 효과를 보강한다.

### 렌더링 구성

- 흐릿한 외부 빛과 색으로 구성한 배경.
- 유리 표면의 얇은 습기 또는 물막.
- 위로 이동하는 크기가 다른 빗방울과 가는 물줄기.
- 글자 내부에서 물막과 물줄기가 줄어드는 발수 영역.
- 글자 경계의 작은 물방울과 절제된 하이라이트.

배경은 첫 버전에서 로컬 에셋이나 절차적으로 만든 색과 빛으로 구성한다.

### 구현 방향

첫 버전의 발수 표현은 텍스트 마스크와 레이어 합성으로 구현하는 시각적 근사다.

- 글자 마스크 내부에서는 물막과 비 표현을 약화한다.
- 글자 경계를 강조해 물이 맺히거나 비켜 흐르는 인상을 만든다.
- 물방울의 기본 이동은 seed와 시간에서 계산한다.
- 전체 유체 시뮬레이션이나 정교한 물방울 병합·분열은 구현 범위에 넣지 않는다.

우선 기본 도형, 마스크, 그라디언트와 제한된 파티클로 원하는 인상이 나는지 확인한다. 커스텀 셰이더는 실제 시각 품질이나 성능상 필요가 확인된 부분에 적용한다.

### 모션과 인터랙션

- 비는 아래에서 위로 계속 흐른다.
- 문구를 적용하면 약 1~2초 동안 발수 영역이 차례로 드러난다.
- 손가락을 드래그하면 주변의 작은 원형 영역에서 물 표현이 잠시 밀려나거나 옅어진다.
- 터치를 놓으면 해당 영역이 부드럽게 원래 상태로 돌아간다.
- 사용자 터치 효과와 문구의 발수 마스크는 별도로 유지한다.
- 일시정지하면 현재 구도를 그대로 감상하고 공유할 수 있다.

### 조절 기능

- 문구
- 배경 분위기: 흐린 낮 / 비 오는 밤
- 비의 강도

시각적 합격 기준: 비가 움직일 때와 정지했을 때 모두 문구가 읽히고, 젖은 유리 안의 발수 영역이라는 인상이 드러나야 한다.

## 8. 렌더링과 상태 구조

두 작품을 독립적으로 이해하고 수정할 수 있게 구성한다.

| 영역                 | 책임                                   |
| -------------------- | -------------------------------------- |
| 라우트와 화면        | 갤러리, 작품 진입, 뒤로 가기           |
| 공통 조작 UI         | 문구 편집, 버튼, 프리셋, 감상 모드     |
| 작품별 모듈          | 각 작품의 설정 타입, 렌더링, 인터랙션  |
| 공통 렌더링 유틸리티 | 좌표 변환, 텍스트 마스크, seed 처리    |
| 내보내기             | 프레임 고정, PNG 생성, 임시 파일, 공유 |
| 로컬 저장            | 작품별 최근 문구와 설정 복원           |

작품 목록은 id, 이름, 설명, 정적·모션 구분, 미리보기 등을 담는 작은 정적 레지스트리로 시작한다.

작품별 설정 타입을 분리하고, 불필요한 범용 플러그인 시스템이나 설정 UI 자동 생성 엔진은 만들지 않는다.

상태는 다음 원칙으로 관리한다.

- 문구와 프리셋, 패널 상태는 React 상태로 관리한다.
- 연속적인 시간, 모션 진행률, 터치 좌표는 Reanimated 등 적절한 실행 경로에서 관리한다.
- 프레임마다 React `setState`로 화면 전체를 다시 렌더링하지 않는다.
- 작품 렌더러에는 문구·설정·seed·시간·인터랙션 상태를 명시적으로 전달한다.
- 작품 렌더러 안에는 편집 버튼이나 공유 버튼을 포함하지 않는다.

작품의 논리 좌표계는 하나로 통일한다. 예를 들어 360×640을 사용하고, 화면 크기와 터치 좌표를 이 좌표계로 변환한다.

## 9. PNG 캡처와 공유

첫 내보내기 형식은 **1080×1920 PNG**다.

사용자가 공유 버튼을 누르면 다음 흐름을 수행한다.

1. 현재 작품의 문구, 설정, seed, 시간, 모션 진행률, 인터랙션 상태를 하나의 프레임 상태로 고정한다.
2. 폰트, 텍스트 마스크, 그래픽 리소스가 준비됐는지 확인한다.
3. 동일한 작품 렌더링 로직으로 목표 해상도의 이미지를 생성한다.
4. 생성된 PNG를 앱의 임시 파일 영역에 기록한다.
5. OS 공유 시트를 연다.
6. 공유 흐름이 끝나면 직전의 재생 상태를 복원한다.

필수 조건:

- PNG에는 작품만 포함한다.
- 제목, 버튼, 키보드, 안내 문구, 워터마크를 넣지 않는다.
- 화면의 낮은 해상도 이미지를 단순 확대하지 않고 목표 픽셀 크기에 맞게 다시 렌더링한다.
- 화면과 PNG의 문구, 구도, seed와 모션 시점이 일치해야 한다.
- 질감과 마스크의 해상도도 출력 크기에 맞게 처리한다.
- 선택한 Skia 버전에서 GPU 텍스처를 포함하는 캡처와 이미지 readback 경로를 확인한다.
- 준비되지 않은 리소스, 크기가 0인 캔버스, 중복 공유 요청을 처리한다.
- 실패 시 짧은 오류 안내와 재시도 경로를 제공한다.
- 공유 취소는 정상 흐름으로 처리한다. 공유 시트가 닫힌 사실을 실제 전달 완료로 단정하지 않는다.
- 공유 중인 임시 파일을 너무 일찍 삭제하지 않으며, 오래된 임시 파일이 계속 누적되지 않게 한다.

앱이 생성한 이미지를 외부로 공유하는 범위로 구현한다. 다른 앱에서 콘텐츠를 받아오는 Share Extension은 필요하지 않다.

## 10. 성능과 접근성

성능 목표는 대표적인 iOS·Android 기기에서 자연스러운 60fps 모션이다. 실제 측정 없이 달성했다고 보고하지 않는다.

- 활성 작품 하나만 애니메이션을 실행한다.
- 화면을 떠나거나 앱이 백그라운드로 이동하면 불필요한 프레임 작업을 중지한다.
- 텍스트 마스크, 천 패턴, 정적 레이어는 재사용한다.
- 스티치 수와 빗방울 수에 상한을 둔다.
- 프레임 루프에서 큰 배열이나 이미지를 반복 생성하지 않는다.
- 저성능 환경에서는 질감의 세밀도나 파티클 수를 먼저 줄인다.

접근성 요구사항:

- 조작 버튼에 이름, 역할, 상태를 제공한다.
- 충분한 터치 영역과 읽을 수 있는 대비를 확보한다.
- 시스템 Reduce Motion이 켜져 있으면 자동 모션을 줄이고 완성된 정지 구도를 기본으로 보여준다.
- 작품의 문구와 현재 상태를 스크린리더가 이해할 수 있게 설명한다.
- 시각적 캔버스 내부에만 중요한 정보나 필수 조작을 숨기지 않는다.

## 11. 구현 순서

### 단계 1 — 기반과 렌더링 확인

프로젝트를 생성하고, 두 플랫폼의 실행 경로를 준비한다.

우선 작은 캔버스에서 번들 한글 폰트, 텍스트 마스크, 간단한 모션, PNG 생성이 선택한 라이브러리 조합에서 동작하는지 확인한다. 이 확인은 곧바로 첫 작품 구현에 연결한다.

### 단계 2 — 자수 작품의 전체 흐름

갤러리 → 자수 작품 → 문구 적용 → 감상 모드 → PNG 공유까지 완성한다.

이 단계가 끝나면 최소한 한 작품은 사용자가 실제로 만들어 공유할 수 있어야 한다.

### 단계 3 — 빗물 작품 추가

공통 진입·편집·공유 흐름을 재사용해 발수 글씨와 위로 흐르는 비를 구현한다.

발수 영역의 가독성과 젖은 유리의 인상이 확보되면 다음 단계로 진행한다.

### 단계 4 — 검증과 정리

두 플랫폼에서 핵심 흐름과 출력 이미지를 확인한다. 시각적 결함, 상태 복원 문제, 불필요한 애니메이션 실행을 수정한다.

새로운 작품을 추가하기 전에 첫 두 작품의 기본 구도와 공유 결과를 완성한다.

## 12. 검증과 완료 기준

자동 검증은 텍스트 입력 검증, seed 재현성, 상태 저장·복원, 내보내기 상태 고정처럼 회귀 위험이 있는 동작에 집중한다. 시각 품질은 실제 렌더링 결과로 확인한다.

다음 항목을 완료 기준으로 사용한다.

- [ ] iOS와 Android 실행 방법이 준비되어 있다.
- [ ] 갤러리에서 두 작품에 진입할 수 있다.
- [ ] 한글·영문 문구를 적용하고 읽을 수 있다.
- [ ] 빈 문구, 길이 초과, 여러 줄, 지원하지 않는 문자를 처리한다.
- [ ] 자수의 글자 형태가 실제 X 스티치로 구성된다.
- [ ] 자수 모션이 끝난 후 완성된 정지 작품을 유지한다.
- [ ] 비가 기본 설정대로 아래에서 위로 흐른다.
- [ ] 유리의 젖은 영역과 발수 글자 영역이 구분된다.
- [ ] 각 작품의 드래그 인터랙션이 동작한다.
- [ ] 감상 모드에 진입하고 다시 나올 수 있다.
- [ ] UI가 없는 1080×1920 PNG를 생성하고 공유 시트를 열 수 있다.
- [ ] PNG의 문구와 구도가 고정한 화면 상태와 일치한다.
- [ ] 폰트와 질감이 출력 이미지에서도 누락되지 않는다.
- [ ] 앱 재실행 시 작품별 최근 문구와 설정이 복원된다.
- [ ] 화면 이탈과 백그라운드 전환 시 모션 작업을 정리한다.
- [ ] typecheck, lint, 핵심 테스트를 실행하고 결과를 기록한다.

4. 두 작품의 실제 화면과 내보낸 PNG 예시.
5. 확인한 플랫폼·기기 또는 시뮬레이터.
